# 全向模块模拟

模拟器作为 TCP client 主动连接平台，默认服务端为 `127.0.0.1:10003`。在“干扰”页设置平台地址、端口和设备 ID，再启动模拟器。

十路默认全关，正常告警字节为 `0x08`。状态由收到的命令更新，不再随机改变开关、功率或告警；关闭时功率显示为 0。频率、温度和功率显示是固定的模拟数据，不代表真实射频测量。

通道顺序与平台一致：433M、915M、1.2G、1.4G、1.5G、1.8G、3.3G、5.2G、2.4G、5.8G。

## 协议支持

帧格式为 `AA + ID(2) + 总长度(1) + CMD(1) + DATA + 55`，ID、频率、地址和保留字段均为小端。

| 命令 | 模拟行为 |
| --- | --- |
| `0x04` | 设置前 N 路开关与功率，N 为 1–10；应答结果 0 成功、非 0 失败。空数据、奇数长度、超出十路或开关值不为 0/1 时整条拒绝，保留原状态。 |
| `0x05` | 返回十路状态，每路 11 字节，总帧长 116 字节。查询不接受附加数据。 |
| `0x10` | 保存小端地址列表；按协议使用 `0x05` 命令码返回单字节结果。空列表或奇数长度返回失败。 |
| `0x11` | 查询当前地址列表。 |

支持 TCP 拆包、粘包及多服务端连接；未知命令忽略，不再伪造成功。状态按查询返回，保持原有不主动上报的行为。日志保留接收 RX、发送 TX 的完整 HEX。

## 运行中测试

展开“更多设置”即可切换故障，连接配置仍需停止后修改。故障模式、故障通道和应答延迟会随场景保存；旧场景自动采用正常模式、0 毫秒延迟。

| 故障模式 | 行为 |
| --- | --- |
| 正常 | 命令执行后正常应答。 |
| 丢弃开关应答 | 执行 `0x04`，丢弃 ACK；仍能查询执行后的真实模拟状态。 |
| 丢弃状态回包 | `0x04` 正常应答，`0x05` 状态查询无回包。 |
| 丢弃全部回包 | 继续接收、执行命令，所有响应静默。 |
| 通道卡在开启 | 指定通道强制开启，关闭 ACK 仍成功，回读保持开启；用于验证平台是否检查实际状态。 |
| 仅返回 9 路状态 | `0x05` 只返回前九路完整数据；用于验证平台拒绝不完整的关闭确认。 |
| 断开网络 | 立即关闭 TCP 并暂停重连，保留全部通道状态。切回正常后按原有 5 秒间隔重连。 |

应答延迟范围为 0–10000 毫秒，停止或断网能立即取消等待。解除“通道卡在开启”只移除故障，原状态要等下一条关闭命令才改变。

验证平台断网恢复时，先开启，再选择“断开网络”，最后切回“正常”。模拟器不会自行补关；平台重连后应发送十路关闭、收到成功 ACK，再查询到完整十路全关。只有这一流程才能证明平台的恢复策略执行成功。停止并重新启动整个模拟器会重置为默认全关，因此应使用故障模式模拟断网。

## 验证记录

2026-11-02 已验证：协议固定报文、小端字段、非法命令原子拒绝、逐字节拆包、粘包、100 轮无等待开启→关闭、应答丢失后的状态回读、故障切换、断线保留开启状态、重连收到关闭后全关、停止取消延迟，以及并发状态快照。独立本机 TCP 测试还覆盖 100 轮瞬间开关与自动重连；不连接真实模块。

```sh
go test -race ./... -count=1
go test -race -tags integration ./internal/modules -run JammingTCP -count=1 -timeout=30s
go vet ./...
cd frontend
bun test
bun run build
```

桌面界面已检查原布局、“更多设置”、运行中的连接字段锁定及故障选项可用。与实际部署平台的联调、真实功放和射频输出不属于这些模拟测试的验证结果。

全量普通和竞态测试中，原有 `TestDetectionUDPServerReturnsAckForCommands` 存在 UDP 监听未就绪即发包的失败，报 `connection refused`；未修改的 HEAD 基线运行该用例 10 次也复现，并报告原有启动/停止竞态。本次未修改侦测模块及其测试，全向相关用例和独立 TCP 集成测试通过。
